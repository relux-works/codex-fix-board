# TASK-260929-4ut0up: watcher-and-output-retention-hooks

## Description
Wire the B1 CompletionReceiptStore into unified exec without exposing it to the model (final plan sections 5 and 5.1, race table 5.4; verdict rev3 note 8; stage 2a, second leaf of STORY p5-completion-receipts). Thin hooks only: (a) UnifiedExecProcessManager owns one CompletionReceiptStore per runtime generation and reserves a receipt before an opted-in launch, where opt-in is a named internal enum (no bool, no tool-schema change: notify_on_exit exposure is story F); (b) the exec_command initial-response decision calls resolve_initial_response, so an exit that precedes arming is returned inline or retained, never lost or duplicated; (c) spawn_exit_watcher publishes the finalized exit to the receipt only at the point it classifies the terminal event today (after exit, output drain, the network-denial monitor settling and the failure/exit-code/timed-out classification), keeping ExecCommandEnd emission unchanged; (d) retained output per receipt survives removal of the process-store entry on exit, capped at 1 MiB with a head/tail split and an explicit truncation indicator plus omitted-byte count; (e) write_stdin terminal output and the pushed completion share one claim; (f) release, terminate, interrupt and shutdown cancel the receipt with the matching CancellationReason before process termination, and release disarms without killing the process. Slot lifetime (note 8): a Sampled receipt with retained output holds its slot until release or retirement; when all 64 slots are held and at least one is a Sampled receipt with retained output, a new reservation retires the least-recently-sampled receipt's output and reads of it report Retired explicitly; with 64 unsampled receipts the 65th reservation is refused before any process starts. No mailbox, context fragment, tool or prompt change (stories C, D, F).

## Scope
codex-rs/core/src/unified_exec: process_manager.rs and async_watcher.rs hooks, a new small module for per-receipt retained output (for example receipt_output.rs with sibling *_tests.rs), and completion_receipt.rs only where a hook needs a missing transition (retirement, owner construction). New tests as sibling *_tests.rs files. No tool specs, handlers, session/input_queue, context or app-server changes. Keep each new module under 500 LoC excluding tests.
