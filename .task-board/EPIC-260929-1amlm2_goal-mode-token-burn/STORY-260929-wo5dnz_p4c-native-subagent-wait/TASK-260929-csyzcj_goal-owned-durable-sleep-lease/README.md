# TASK-260929-csyzcj: goal-owned-durable-sleep-lease

## Description
Goal-owned durable-sleep lease so queue-only native subagent results wake a waiting goal parent (final plan section 7; leaf 1 of STORY p4c-native-subagent-wait; stacked on landed P5-2e). At goal idle, inspect the goal thread's DIRECTLY OWNED native children through a narrow, private typed inspection of owned registry entries (Loaded/Unloaded/error; errors propagate, not silently skipped like list_agents). Loaded PendingInit/Running work on a persistent host permits registration. Non-goal, unloaded or unknown work gets no marker. Reused children use their current state, and Completed means turn ended, not goal achieved. Registration is a goal-owned SleepItem with id `goal-wait:<generation>` in thread extension data, inserted with insert_if (only if absent or already its own). It never clobbers another contributor's sleep. Insert the marker BEFORE checking pending mail, then call the existing pending-work scheduler or recheck; this closes completion-before-registration. Storing the marker emits no tool events, schedules nothing, records no history item and does not change current-time reminders; the goal scheduler owns the timer and warning. Apply section 6's check-ins (reuse the P4a scheduler). Removal is an atomic conditional remove of only the owned id, on: the next admitted turn start, goal inactive/clear/disable, thread stop, or explicit wait release. On a check-in, remove the marker for that admitted turn and reinsert it if still waiting at idle. Keep it while check-ins are exhausted so a late completion can still wake. Resume never revives a marker from a rendered SleepItem or for an unloaded child. Interrupted children: for a registered wait, the status watchers emit a queue-only Interrupted notice once per transition, without redefining the global is_final and without claiming success. Any mailbox mail may wake the durable sleep (intended), with inherited turn settings preserved. Out of scope: the V1 notification bridge (sibling TASK-260929-3rdnra, G2).

## Acceptance Criteria
AC1 A goal parent with a Running native child registers the owned marker at idle; the child's queue-only completion then wakes the parent (asserted model request, not just marker presence). AC2 No marker is created for non-goal threads, unloaded or unknown children, or failed inspection. Errors propagate (narrowing mutant: skip failed lookups). AC3 Completion-before-registration is closed: a child finishing between the idle check and the insert still wakes the parent (latch test; mutant: insert after the mail check). AC4 insert_if never clobbers a foreign SleepItem, and the conditional remove only removes the owned id (a test with a foreign marker present; mutant: unconditional remove). AC5 Removal on admitted turn start, goal clear/disable, thread stop and release. On a check-in it is removed, then reinserted at idle if still waiting. It is kept after the check-ins are exhausted, and a late completion wakes. AC6 No sleep UI events, no history item and no reminder change from storing the marker (asserted). AC7 An Interrupted child yields one queue-only notice per transition, and global is_final is unchanged. AC8 Reused, error and second-child-mid-turn cases behave per state. Inherited turn settings are preserved on wake. AC9 Resume does not revive the marker.
