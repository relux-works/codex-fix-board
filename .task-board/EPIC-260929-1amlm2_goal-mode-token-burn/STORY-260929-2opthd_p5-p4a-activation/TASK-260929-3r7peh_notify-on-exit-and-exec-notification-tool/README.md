# TASK-260929-3r7peh: notify-on-exit-and-exec-notification-tool

## Description
Activate completion notifications together with the goal background-wait policy (final plan 5.1, 5.3, 6 and 10 stage 2e; leaf 1 of STORY p5-p4a-activation; stacked on landed P4a, relux/main 2f522b9). Until now everything from stages 2a-2d is inactive; this leaf turns it on, for capable hosts only. (1) Host capability: add AsyncNotificationSupport to codex-extension-api, defaulting to Unavailable. Enable it ONLY for verified persistent hosts through the existing extension init (app-server thread processor and thread_manager init; re-locate the plan citations). Headless exec, which shuts down at TurnCompleted, and all its descendants stay Unavailable; inheritance is explicit, and 'not Exec' is not enough. (2) exec_command gains an opt-in `notify_on_exit: true` argument (default false), exposed in the tool schema ONLY when the host capability is Available. Opting in reserves one of the 64 receipt slots before launch and refuses before execution when full (separate from the 64-process cap). Never arm automatically on every yield or stdin poll. (3) New tool `exec_notification` with tagged actions `read {receipt_id, max_output_tokens?}` (returns terminal retained output; not a new blocking or liveness poll; small default; under 10K tokens per item; truncation indicated) and `release {receipt_id}` (disarms without killing the process, or retires retained output, and frees the slot). It rejects stale, foreign and unknown receipts, and is advertised only on capable hosts. (4) Local tool descriptions state exactly what is promised: a wake on exit only when notify_on_exit was accepted, and that release disarms without killing. No promise is made on incapable hosts. Defer any no-wait/end-turn paragraph (it depends on P4b). (5) Activate the P4a goal background-wait policy (enabled where the host capability is Available) so pending opted-in work gates goal continuation. Out of scope: the app-server vertical test (sibling TASK-260929-3f6hfg, F2), P3 capability flags, P4b pacing, P4c subagent wait.
