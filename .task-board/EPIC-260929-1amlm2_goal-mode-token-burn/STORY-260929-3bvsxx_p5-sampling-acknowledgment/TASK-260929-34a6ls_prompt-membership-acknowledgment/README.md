# TASK-260929-34a6ls: prompt-membership-acknowledgment

## Description
Sampling acknowledgment by prompt membership (final plan 5.2 'Acceptance = included in a sampling request'; stage 2c, leaf 1 of STORY p5-sampling-acknowledgment; stacked on landed P5-2b, relux/main 22b9fb6). Track the trusted receipt ids of C1 runtime-notification entries and C2 ExecCompletionFragments through pending input, the single history append and the final assembled prompt. A lease is acknowledged as sampled ONLY after the request that actually contains the fragment is successfully submitted on the selected transport (HTTP or WebSocket, including the HTTP/WS fallback selection; re-locate the plan's turn.rs:2539-2552 and client.rs:2218-2266 citations at your base). Reservation, drain, pending-input recording and history append never acknowledge. Membership is checked against the submitted prompt items (trusted ids from the runtime lease, never parsed from fragment text). A failed submission leaves the lease unacknowledged and returns it unleased through C1's fail path, so it is retried. Existing bounded transport retries apply. After exhaustion the entry is retained or suspended visibly (C1 suspended state), and never spawns endless wake turns. A fragment already recorded in history but unsampled is retried without appending it a second time. Normal history repetition in later requests is not duplicate delivery and does not re-acknowledge. Out of scope: the F1a/F1b and compaction/guardian regression suite (D2), process publication (E), tool exposure (F).

## Acceptance Criteria
AC1 Successful HTTP submission of a request containing the fragment acknowledges exactly that receipt; the lease is then gone. AC2 Same over WebSocket, and through the HTTP/WS fallback path. AC3 Reservation, drain, pending-input recording and history append alone never acknowledge (a narrowing mutant acknowledging on append must fail a named test). AC4 A failed or aborted submission returns the lease unleased; the retry samples it once, with no second history append of the same fragment. AC5 After bounded retries are exhausted, the entry is suspended visibly: no further wake turns and no spin (asserted request count). AC6 Membership uses trusted lease ids: a forged fragment text in the prompt or history acknowledges nothing. AC7 A receipt omitted from the submitted prompt (for example, cut by the batch cap) stays pending and is sampled by a later request.
